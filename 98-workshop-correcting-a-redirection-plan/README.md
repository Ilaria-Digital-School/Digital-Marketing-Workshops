# Workshop: correcting a redirection plan

THEORETICAL RECAP A redirection plan is the structured mapping of old URLs to new URLs during a site migration, restructuring, or cleanup. The two most common HTTP status codes you must master are the 301 (permanent redirect, which transfers most of the link equity to the destination) and the 302 (temporary redirect, which does not transfer SEO value durably). The correct mental model is a chain of arrows: each old URL should point in a single hop to its most relevant, still-live equivalent. Every broken link (404) or dead-end must resolve to a meaningful page, never to the homepage by default when a closer topical match exists. Common mistakes include: redirect chains (A to B to C instead of A to C), redirect loops (A to B to A), using 302 where a 301 is required, redirecting massively to the homepage (soft signal of low relevance), and forgetting to preserve the trailing-slash and HTTP/HTTPS consistency. A mini example: an e-commerce site deletes /shoes/red-sneakers. A weak plan sends it to /home. A correct plan sends it via 301 to /shoes/sneakers, the closest surviving category, in one hop, preserving user intent and passing link equity. Keep this rule in mind: relevance first, single hop always, correct status code every time. WORKSHOP BRIEF You will receive (or reconstruct) a flawed redirection plan for a fictional mid-sized website that recently migrated its structure. The plan contains around 25 to 30 mappings mixing correct redirects, chains, loops, wrong status codes, irrelevant destinations, and missing entries....
