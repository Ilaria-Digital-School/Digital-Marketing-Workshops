# Workshop: manipulating robots.txt and sitemap on a sandbox

THEORETICAL RECAP A robots.txt file is a plain text file placed at the root of a domain (example.com/robots.txt) that tells crawlers which URLs they may or may not request. It uses simple directives: User-agent (which robot the rule targets), Disallow (paths to block), Allow (exceptions within a blocked path), and Sitemap (the URL of your sitemap). The mental model to keep in mind: robots.txt controls CRAWLING, not INDEXING. Blocking a URL in robots.txt does not guarantee it stays out of Google's index; a blocked page can still appear in results (without a description) if other pages link to it. To keep a page out of the index, you use a noindex meta tag or header, which requires the page to be crawlable. A sitemap.xml, by contrast, is a suggestion: it lists the URLs you WANT crawled and indexed, with optional metadata (lastmod, priority, changefreq). Common mistakes: using Disallow to try to hide sensitive data (it does the opposite, revealing the path), blocking CSS/JS the renderer needs, forgetting the leading slash, mixing up 'Disallow: /' (block everything) with 'Disallow:' (block nothing), and referencing a sitemap that returns a 404. Mini example: User-agent: * Disallow: /admin/ Allow: /admin/public/ Sitemap: https://example.com/sitemap.xml This blocks all robots from /admin/ except /admin/public/, and points them to the sitemap. WORKSHOP BRIEF Your goal is to design, build, and validate a coherent robots.txt file and an accompanying sitemap.xml for a small fictional e-commerce website, then verify that your crawl directives behave exactly as intended.
