# Workshop: observe the crawl with Screaming Frog

THEORETICAL RECAP In the previous lesson you learned how a search engine crawls the web: a bot (like Googlebot) starts from known URLs, reads the HTML, follows the links it finds, and repeats the process to discover new pages. Crawling is the discovery phase; indexing is the storage phase; ranking is the ordering phase. A useful mental model is to picture the crawler as a visitor who can only move by clicking links: if a page has no incoming link, or is blocked by robots.txt, or returns an error, the visitor never reaches it. Screaming Frog SEO Spider is a desktop tool that mimics this behaviour. You give it a starting URL and it crawls the site like a search engine would, collecting for each URL its HTTP status code (200, 301, 404, 5xx), title tags, meta descriptions, headings, canonical tags, and internal links. This lets you see your site the way a bot sees it. Common mistakes: confusing a 301 redirect with a broken link, ignoring pages blocked in robots.txt, or assuming a page is indexable simply because it loads in a browser. Mini example: you crawl a blog and find 15 URLs returning 404 that are still linked from your menu. Those are dead ends wasting crawl budget and hurting user experience, and they must be fixed or redirected.
